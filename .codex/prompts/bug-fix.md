# 버그 수정 작업 규칙

버그 수정 시 첫 번째 의심 코드를 바로 수정하지 않는다.

## 분석 순서

1. 오류 발생 Entry Point 확인
2. 실행 흐름 추적
3. 데이터 흐름 추적
4. 관련 Event/Callback/Caller 확인
5. 관련 DB/API 호출 확인
6. 유사 로직 확인
7. 실패 조건 특정
8. Root Cause 결정
9. 영향 범위 결정

## 수정

- 증상보다 원인을 수정한다.
- 가장 작은 안전한 변경을 선택한다.
- 관련 없는 Refactoring은 하지 않는다.
- 기존 정상 동작을 보존한다.

## 완료 시

다음을 보고한다.

- 현상
- Root Cause
- 수정 방법
- 수정 파일
- 영향 범위
- Regression Risk
- 검증 방법 및 결과

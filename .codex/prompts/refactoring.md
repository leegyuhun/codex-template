# 리팩터링 작업 규칙

리팩터링의 목적은 동작을 바꾸지 않고 구조를 개선하는 것이다.

## 시작 전

- 리팩터링 대상과 이유를 명확히 한다.
- 현재 동작과 Public Contract를 확인한다.
- 충분한 테스트 또는 검증 수단이 있는지 확인한다.
- 작업 범위를 제한한다.

## 원칙

- 기능 변경과 리팩터링을 가능하면 분리한다.
- 한 번에 여러 Architecture Concern을 바꾸지 않는다.
- Naming/Folder/Dependency 변경은 실제 이득이 있는 경우에만 한다.
- 대규모 변경은 단계적으로 진행한다.

## 완료 시

동작 변경 여부, 구조적 개선점, 테스트 결과, 남은 위험을 보고한다.

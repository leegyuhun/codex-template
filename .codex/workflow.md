# 개발 작업 흐름

## 표준 순서

1. `AGENTS.md`와 관련 규칙을 읽는다.
2. 요청한 최종 결과를 정확히 해석한다.
3. 관련 Entry Point를 찾는다.
4. 호출 관계, 데이터 흐름, 의존성을 추적한다.
5. 기존 유사 구현을 찾는다.
6. 회귀 및 호환성 위험을 확인한다.
7. 가장 작은 합리적인 구현 계획을 세운다.
8. 코드를 수정한다.
9. 테스트/빌드/검증을 수행한다.
10. Diff를 다시 확인하여 관련 없는 변경이 없는지 점검한다.
11. 결과를 보고한다.

## 작업 전 정리

복잡한 작업은 구현 전에 다음을 정리한다.

- 무엇을 변경해야 하는가
- 어느 파일/모듈이 영향을 받는가
- 무엇은 반드시 그대로 유지되어야 하는가
- DB/API/UI/파일 포맷 영향이 있는가
- 어떤 방식으로 검증할 것인가

## 범위 통제

작업 중 인접 문제를 발견한 경우:

- 현재 작업을 완료하기 위해 반드시 필요하면 함께 수정한다.
- 그렇지 않으면 임의로 범위를 넓히지 말고 별도 이슈로 보고한다.

## 자동 생성 파일

Generated Code, Designer File, ORM Generated File 등 자동 생성 파일은 직접 수정하기 전에 생성 원본 또는 생성 절차를 확인한다.
가능하면 Source of Truth를 수정하고 재생성한다.

## 문서 업데이트

다음 경우 관련 문서를 함께 업데이트한다.

- 새로운 중요한 Architecture Decision이 생김
- 외부 API Contract가 변경됨
- DB Schema 또는 운영 절차가 변경됨
- 알려진 제약/문제가 추가됨
- Build/Deploy 방법이 변경됨
